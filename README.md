# server-myhome

Сервер умного дома: WebSocket-обмен с клиентом Vue 3 (Dashboard) и NodeRED, опрос устройств по Modbus TCP
и Modbus RTU (RS-485), видеонаблюдение на 1–16 камер (RTSP и муляжи → кадры в клиент, архив в S3),
оповещения в Telegram, управление замком через GPIO.
Протокол обмена, права доступа и правила разработки — в [rules.md](rules.md).

## Запуск

```bash
npm ci
cp conf_example conf.env   # заполнить JWT_SECRET, порты, Modbus, видео, Telegram
npm start                  # node serverapp.js
npm run dev                # то же под nodemon (перезапуск при изменении кода)
```

Каталоги данных (в git не попадают): `data/` — пользователи и ключ шифрования,
`.configData/` (`DATA_DIR`) — конфигурации dID и `modbusMap.json`, `tmp/` — видеоархив до выгрузки.

## Тесты

## Инструменты

- `node tools/modbusSlaveEmulator.js --port 5020 [--jitter]` — эмулятор Modbus TCP-устройства по `modbusMap.json`
  (консольные команды `list`, `get`, `set`, `jitter on|off`). Для работы сервера с ним:
  `MODBUS_DEVICES='[{"id":"pr205","host":"127.0.0.1","port":5020,"unitId":1}]'`.
- `node tools/modbusDiag.js --host 192.168.10.5 [--port 502] [--unit 1]` — прочитать все теги карты
  с устройства (или эмулятора) и показать сырые регистры и значения.
- Камеры и муляжи: [docs/cameras.md](docs/cameras.md) — при первом запуске без камер создаётся `cameras.json` с 4 муляжами.
- `node tools/videoLoadTest.js [--cameras 1,4,8,16] [--clients 2] [--duration 30]` — нагрузочная проверка видео:
  сервер с N тестовыми камерами (ffmpeg генерирует картинку) и M клиентами; доставка, задержка, трафик, CPU и память.
  Без ffmpeg — `--ffmpeg fake` (проверка цепочки и сети, без нагрузки кодирования).
- `node scripts/authAdmin.js` — администрирование пользователей из консоли.
- `node tools/modbusRtuCheck.js [master|crc|manager]` — проверка Modbus RTU без железа на виртуальных портах
  (`tools/ptyPair.py`, нужен python3).
- `modBus/` — Modbus RTU (Master/Slave по RS-485), включается `MODBUS_RTU_ENABLED=true`: см. [docs/modbus-rtu.md](docs/modbus-rtu.md).

## История

### version_0_0_3_1 — 18.11.26

**Видеонаблюдение**
- 1–16 камер в `.configData/cameras.json`: реальные (RTSP) и муляжи (ffmpeg генерирует картинку) вместе.
- При первом запуске файл создаётся сам: 4 муляжа (`VIDEO_MOCK_CAMERAS`) и камера из `VIDEO_RTSP_URL`, если задан.
- Правка `cameras.json` применяется без перезапуска: перезапускаются только изменённые камеры, клиентам приходит
  новый список; файл с ошибкой JSON не останавливает работающие камеры.
- Доставка по подписке: миниатюры только видимых карточек, кадр полного экрана раз в секунду; кадр кодируется
  один раз на всех получателей, медленному клиенту пропускается.
- Доступ: `dID` камеры — один, список или `"*"` (все пользователи); значение по умолчанию — `VIDEO_DID`.
- Проверка ffmpeg при старте с подсказкой установки.
- Нагрузочная проверка без камер: `tools/videoLoadTest.js` (MacBook Pro: 16 камер 720p — 73 % одного ядра на ffmpeg,
  доставка 100 %, задержка 1–6 мс).
- Инструкция: [docs/cameras.md](docs/cameras.md).

**Modbus TCP**
- Логические теги в регистрах (`item_type: bool`) публикуются как да/нет.
- Значение из клиента сохраняется и рассылается только после подтверждения записи контроллером.
- Эмулятор: исправлены дрожание значений и `defaultScale`/`defaultOffset`; новая диагностика `tools/modbusDiag.js`.
- Инструкция: [docs/modbus-tcp.md](docs/modbus-tcp.md).

**Modbus RTU**
- Подключён к серверу (`services/modbusRTUBridge.js`, `MODBUS_RTU_ENABLED`): значения в клиент, запись уставок
  и команд в устройства, записи внешнего контроллера в клиент.
- Master: одна очередь запросов на шине (запись не сталкивается с опросом); поле `id` — несколько устройств
  одного пользователя.
- Slave: проверка контрольной суммы (CRC) входящих кадров; параметры шины `parity`, `dataBits`, `stopBits`;
  корректный запуск и ошибка при недоступном порте.
- Роль `master` / `slave` / `both` из файла или `MODBUS_ROLE`, запрет двух ролей на одном порту.
- Проверка без железа: `tools/modbusRtuCheck.js` (виртуальные порты).
- Инструкция: [docs/modbus-rtu.md](docs/modbus-rtu.md).

**Безопасность**
- Убрано автооткрытие замка через 30 с после старта; выходы GPIO при старте выключены.
- `dID` проверяется на всех уровнях — запись файла вне `DATA_DIR` невозможна.
- Канал NodeRED по умолчанию слушает только `127.0.0.1` (`WSR_HOST`).

**Сессии и обмен с клиентом**
- Сессия живёт, пока открыто соединение; `AUTH_TIMEOUT_MS` — время на вход (код закрытия 4401).
- Приветствие `serverConnected` — один раз новому соединению.
- Изменение из одной вкладки приходит в другие вкладки того же пользователя и без NodeRED.

**Надёжность и логирование**
- Параллельные записи в один файл конфигурации идут по очереди; сообщение с ошибкой больше не повторяется бесконечно.
- Уровни `LOG_LEVEL` исправлены: ошибки пишутся всегда; ошибки сокетов клиента логируются.
- Предупреждение, если переменная окружения терминала перекрывает `conf.env`.

**Зависимости и чистка**
- Node.js 20+; Express 5, Joi 18, dotenv 18, Jest 30; удалены неиспользуемые пакеты (axios, body-parser, pg, uuid…).
- Удалены мёртвый код, мусор и артефакты сборки; `conf_example`, `rules.md` приведены к коду.
- Тесты: 22 набора, 502 теста.
